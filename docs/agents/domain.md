# Domain docs

## Layout

This repository uses a single-context layout:

- GLOSSARY.md at the repository root
- Architecture decision records in docs/adr/

## Before exploring

Read GLOSSARY.md and the ADRs relevant to the work.
If they do not exist, proceed silently. Create them when domain
terms or architectural decisions are resolved.

## Vocabulary and decisions

Use the glossary’s terms in issues, proposals, hypotheses, and tests.
Flag gaps for domain-modeling when needed.

If a proposal conflicts with an existing ADR, identify the ADR and
explain why the decision should be reconsidered.
